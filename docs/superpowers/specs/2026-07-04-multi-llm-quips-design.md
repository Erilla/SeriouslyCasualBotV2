# Multi-LLM Signup Quip Generation + Overlord Names

**Date:** 2026-07-04
**Status:** Design approved, pending spec review

## Problem

Signup reminder quips (`src/functions/raids/alertSignups.ts` → `src/services/quipGenerator.ts`)
are generated by a single LLM (Google Gemini 2.0 Flash), falling back to a static
hand-written corpus when the key is unset or the call fails. Two changes are wanted:

1. **More generation resilience:** add two more LLM providers so a Gemini outage
   (or missing key) still yields a freshly-generated quip before dropping to the
   static corpus.
2. **Overlord names instead of hardcoded leaders:** the prompt currently hardcodes
   `Warzania, Bing, Splo`. Use the guild's configured **Overlords** (the `overlords`
   DB table, `name` + `user_id`, managed via `/settings`) instead, so quips reference
   whoever currently runs the guild.

## Provider cascade

`generateSignupQuip` tries providers in a fixed order; the first that returns a
valid, non-empty, in-length quip wins. Each provider is skipped (not errored) when
its API key is unset, and falls through on error, timeout, or malformed output:

```
Gemini  →  OpenAI  →  Claude  →  static V1 corpus (never fails)
```

- Each provider is an `async` function returning `string | null`
  (`callGemini`, `callOpenAI`, `callClaude`). None throws to the orchestrator; the
  orchestrator wraps each in try/catch and moves to the next on `null`/throw
  (mirrors the current Gemini try/catch).
- All three reuse the existing `buildPrompt`, `normalizeQuip`, and the
  `MAX_QUIP_LENGTH` (280) guard, so prompt construction and output cleanup are
  written once.
- The static corpus (`V1_SAMPLE_QUIPS` + `randomFallback`) remains the terminal
  fallback and is unchanged.

## Implementation style

Raw `fetch` + `AbortController` with the existing 5s timeout
(`REQUEST_TIMEOUT_MS`) for all three providers, matching the current Gemini code.
**No new npm dependencies.**

| Provider | Endpoint | Auth | Model | Response path |
|---|---|---|---|---|
| Gemini | `…/gemini-2.0-flash:generateContent` (existing) | `x-goog-api-key` | gemini-2.0-flash | `candidates[0].content.parts[].text` |
| OpenAI | `https://api.openai.com/v1/chat/completions` | `Authorization: Bearer` | `gpt-4o-mini` (default, easily changed) | `choices[0].message.content` |
| Claude | `https://api.anthropic.com/v1/messages` | `x-api-key` + `anthropic-version: 2023-06-01` | `claude-haiku-4-5` | `content[0].text` |

Notes:
- **Claude model = `claude-haiku-4-5`** deliberately: a one-line quip does not warrant
  Opus/adaptive thinking. Haiku 4.5 takes a plain Messages request (`max_tokens: 120`,
  no `thinking` / `effort` config — `effort` errors on Haiku).
- API keys sent in headers, never query params (consistent with the existing
  Gemini `x-goog-api-key` choice).

## Config

`src/config.ts`: add two optional lazy getters alongside `geminiApiKey`:

```ts
get openaiApiKey() { return process.env.OPENAI_API_KEY ?? ''; }
get anthropicApiKey() { return process.env.ANTHROPIC_API_KEY ?? ''; }
```

Lazy getters (not `optional(...)` at construction) so tests can toggle env vars
between cases — same reasoning as the existing `geminiApiKey` getter. Update
`.env.example` with the two new (optional) vars.

A provider whose key is empty is silently skipped in the cascade.

## Overlord names in the prompt

- **Data source:** `getOverlords()` (`src/functions/raids/overlords.ts`) returns
  `OverlordRow[]`. `alertSignups` already holds a DB handle, so it resolves the names
  and passes them in — `quipGenerator` stays DB-free and unit-testable.
- **Wiring:** add `overlordNames: string[]` to `GenerateQuipOptions`. `alertSignups`
  calls `getOverlords().map(o => o.name)` and passes the array.
- **Prompt (`buildPrompt`):** the tone line changes from
  *"Occasionally reference guild leaders (Warzania, Bing, Splo)."* to
  *"Occasionally reference the guild's Overlords ({names})."* when names are present.
- **Empty list → skip name references entirely:** when `overlordNames` is empty, the
  leader-reference clause is dropped from the prompt; quips stay generic. No hardcoded
  trio remains anywhere in the code.

## Logging

- Per-provider failure: `logger.warn('QuipGen', ...)` (as today).
- On success: a `logger.debug('QuipGen', ...)` noting which provider produced the quip.

## Testing

Extend `tests/unit/quipGenerator.test.ts`, mocking `fetch` per provider:

- Gemini fails → OpenAI used.
- Gemini + OpenAI fail → Claude used.
- All three fail (or all keys unset) → static corpus fallback.
- Provider with unset key is skipped without a network call.
- `buildPrompt` includes Overlord names when present; omits the leader clause when
  `overlordNames` is empty.

## Out of scope

- No change to the cron schedule, the unsigned-raider logic, or the mention-building
  in `alertSignups`.
- No provider-selection setting / UI — order is fixed in code.
- No streaming, retries, or SDK adoption.
